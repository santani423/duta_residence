# Manajemen Pengguna — Kasus Uji

## Ikhtisar

Modul ini mencakup pengelolaan akun staf/admin internal yang diekspos oleh `UserController` (`api/v1/users*`) dan UsersPage/UserDetailPage pada aplikasi web React Admin. Aksi yang dicakup: menampilkan daftar dengan pencarian/filter/paginasi (`users.view`, hanya diurutkan berdasarkan yang paling baru dibuat — tidak ada pengurutan yang dapat dikonfigurasi), membuat pengguna (`users.create`), melihat detail pengguna (`users.view`), memperbarui pengguna (`users.update`), menghapus pengguna secara soft-delete (`users.delete`), reset password yang dipicu oleh admin (`users.reset-password`), mengalihkan status aktif/nonaktif (`users.activate`), dan melihat umpan aktivitas audit-log milik pengguna sendiri (`audit-logs.view`, berbeda dari `users.view`). Perlu dicatat bahwa role `collector` dan `supervisor` sama sekali tidak dapat ditetapkan atau dikelola melalui layar Manajemen Pengguna generik ini — kedua role tersebut memiliki modul manajemen khusus tersendiri (Manajemen Kolektor/Supervisor) yang membuat baris profil terkait secara atomik; upaya untuk menetapkan `role: collector` atau `role: supervisor` di sini akan ditolak oleh validasi. Riset yang tersedia untuk modul ini menemukan **tidak ada proteksi eksplisit terhadap akun sendiri atau "admin terakhir yang tersisa"** di mana pun dalam `UserController::destroy()` maupun `toggleStatus()` — skenario penghapusan/penonaktifan akun sendiri dan admin terakhir disertakan di bawah ini sebagai kasus batas untuk memverifikasi perilaku aktual terhadap aturan bisnis yang dimaksudkan, bukan sebagai aksi yang telah dipastikan diblokir sebelumnya. Semua endpoint berada di bawah `api/v1`, merespons melalui envelope `ApiResponse` standar, dan memerlukan `auth:sanctum`. Modul ini hanya berlaku untuk Web Admin / API Backend — tidak ditemukan eksposur pada portal penghuni atau aplikasi Android untuk manajemen pengguna itu sendiri.
