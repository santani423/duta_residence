# Kasus Uji Autentikasi & Manajemen Sesi

Dokumen ini mencakup kasus uji black-box untuk permukaan autentikasi dan manajemen sesi Duta Residence: login, logout, pengambilan data pengguna saat ini, ganti password, halaman lupa/reset password, penerapan sesi tunggal (single-session), penanganan kedaluwarsa sesi (401), dan kunci biometrik pada aplikasi Android. Backend Laravel + Sanctum yang sama (`api/v1/auth/*`) melayani tiga front-end: SPA web React Admin/Resident (satu halaman `/login` bersama untuk role staf maupun penghuni/customer) dan aplikasi Flutter Android (satu layar login bersama untuk role penghuni, kolektor, dan supervisor, yang kemudian bercabang ke shell home sesuai role setelah autentikasi berhasil). Semua pesan validasi/error backend yang dikutip di bawah ini adalah string literal Bahasa Indonesia yang diambil dari kode sumber; jika tidak ada pesan literal di sumber, hasil yang diharapkan dijelaskan secara umum. Kode Modul: **AUTH**.

### 5. Lupa Password & Reset Password (Web)

> **Catatan — Kesenjangan fungsionalitas:** Tidak ada satu pun route backend untuk alur self-service lupa password atau reset password di `routes/api.php`. `ForgotPasswordPage` (`/forgot-password`) dan `ResetPasswordPage` (`/reset-password`) pada aplikasi web hanya ada sebagai **placeholder non-fungsional**: input dan tombol submit-nya dinonaktifkan, tidak ada request network yang pernah dikirim, dan setiap halaman menampilkan alert informasi yang menyatakan bahwa reset password publik belum tersedia dan admin dengan permission `users.reset-password` harus mereset akun tersebut dari User Management sebagai gantinya. Kasus uji di bawah ini memverifikasi perilaku (kesenjangan) saat ini, bukan alur reset yang berfungsi.

### 6. Penerapan Sesi Tunggal (Single-Session)

> **Catatan — Ruang lingkup penerapan:** Middleware `single-session` pada backend (`EnsureSingleSession`) hanya diterapkan pada grup route `resident/*` (yaitu role `customer`/penghuni, baik di Portal Web Penghuni maupun aplikasi Android). Route staf/admin (`UserController` dsb.) tidak memiliki pembatasan tersebut, sehingga akun staf di Web Admin — dan akun `collector`/`supervisor` di Android, yang endpoint-nya juga berada di luar `resident/*` — saat ini dapat memiliki sesi/token konkuren tanpa batas. Kasus uji di bawah ini mencakup baik kasus yang sudah diterapkan (customer) maupun perilaku yang saat ini belum diterapkan (staf/kolektor/supervisor).
