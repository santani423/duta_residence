# Collector Management — Black-Box Test Cases

This document covers the Collector Management surface of Duta Residence: collector employee profile CRUD and status lifecycle (`CollectorController`), collector-to-resident/unit/cluster/block assignment and reassignment (`CollectorAssignmentController`), collector GPS location pings and the staff-facing live map feed (`CollectorLocationController`), collection target/quota CRUD (`CollectorTargetController`), performance scorecards (`CollectorPerformanceController`/`CollectorPerformanceService`), and WhatsApp-based payment reminders logged by collectors (`CollectorReminderController`). It also covers the collector-specific screens of the shared Flutter Android app: Unit Saya (assigned units list), unit detail, Rute (route map), Notifikasi, and Profil. Field-visit logging, evidence upload, payment-promise (PTP) capture, and collection letters are covered in `docs/testing/12_service_tracking.md` and are only referenced here for context, not duplicated. Every backend endpoint sits behind `auth:sanctum` plus the global `audit` middleware and Spatie permission gates (`permission:a|b` = either permission satisfies the gate).

A recurring, confirmed finding threaded through this document: **GPS is NOT strictly enforced for collectors in the current build.** The Android collector shell pings `POST collector-locations` on mount and then every 5 minutes only while a collector screen is on-screen (foreground-only, best-effort); any failure (permission denied, GPS off, timeout) is caught and silently ignored, with no blocking dialog, warning, or nag anywhere. A collector can use every feature of the app — including logging visits, recording payments, and viewing units — with location permission permanently denied. The only visible symptom is that the collector appears under the supervisor dashboard's "Tanpa Lokasi" / `not_sending_location` count. Test cases below document this as **current behavior to verify**, not as a defect to file against.
