# Kasus Uji Matriks Otorisasi Role & Permission (RBAC)

Dokumen ini menguji **penerapan (enforcement)** model permission Duta Residence. Tidak ada UI atau API manajemen role/permission yang dinamis di mana pun dalam sistem ini — role (`root, super_admin, admin_estate, back_office, finance, property_manager, operations_staff, security, technician, vendor, loket, cs, collector, supervisor, customer`) dan penetapan permission-nya bersifat tetap sejak waktu deploy melalui database seeder (`RolePermissionSeeder`); tidak ada layar atau endpoint "buat role"/"tetapkan permission" untuk diuji. Setiap route API admin/staf dijaga oleh middleware Spatie `permission:<key>` (kegagalan berupa `AuthorizationException` dipetakan ke HTTP 403); setiap route mensyaratkan `auth:sanctum` (token yang tidak ada/tidak valid dipetakan ke HTTP 401); role `customer` (penghuni) di-seed dengan **nol** permission admin (`permissions => []`) dan sebagai gantinya dibatasi hanya pada prefix route `resident/*` melalui gate `role:customer`. Role `collector` dan `supervisor` memiliki subset permission yang berfungsi, dibatasi hanya pada data yang ditugaskan kepada mereka sendiri (diterapkan di dalam controller, bukan hanya melalui permission gate). Dokumen ini menguji sampel representatif yang luas berupa ≥20 permission string di seluruh sistem, beserta batasan data/aksi berbasis role yang dihasilkannya, dan perilaku otorisasi sisi klien (web) yang mencerminkan aturan yang sama. Kode Modul: **RBAC**.
